Asks for a typed decision about a short state, to put work in order: a Choice among up to 255 options (`options`, key to text), a Score among 2 to 10 ordered `levels`, or a yes or no (`noul`). It returns the `answer`, the `probabilities` over the labels (`yes` and `no` for a yes or no), the backend that answered, the model as it named itself and the cost in dollars. The probabilities are for ordering only: no threshold may be put on them until the site has a reliability curve built from Lean outcomes. Only the sites in the input's `site` list accept it, and it is never used for the fidelity of a statement, for anything Lean or a tool can decide, for a claim's status or for generation.

This capability holds the backends that leave the process: `jev` (the state and the question go to a third party, over HTTP, with a key and a model pinned in the environment, to a host the profile allows) and `faux` (scripted, for tests). A request of more than 32k tokens is refused by `jev`. The default backend, the run's own model, is not an implementation here: it is the line's `decide`, which falls back to it when `jev` cannot answer (documentation/decide.md).

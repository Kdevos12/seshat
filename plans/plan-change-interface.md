# Plan change: user control, UI and UX of the interface (UX1 to UX16)

Status: UX1 and UX2 (the two P0 items) APPROVED by the owner 2026-11-17 23:34 UTC ("Go avec ce qui est critique"), relayed to the build thread; UX3 to UX16 PROPOSED, not approved. Proposed 2026-11-17 by the thread "Auditer l'interface : contrôle, UI et UX" (read-only on the repository and the plan). The findings behind it, with screenshots, are in French in `research/audit-interface.md` and `research/audit-interface/`.

## Evidence in one paragraph

Audit of main `9f0c422` (after PRs #2 and #3; PR #4 read, not merged). The web interface (`harness ui`, `packages/ui`) was driven in Chromium by its own browser test on a scripted journal; the CLI (`solve`, `doctor`, `report`) was run in a container without Lean or Kimina. Trust handling is strong and must be kept: spend ceiling always present, signature before spend, evidence never shown as proof, Stop reaches the whole process group, `RESULT.md` written at every stop, keys never echoed. Two defects mislead the user: `cheapestModel` (`student.ts:160`) has no capability filter and here chose `amazon-bedrock/mistral.voxtral-mini-3b-2507` (a 3B speech model) from ambient AWS credentials; the settings panel shows `RunConfig` defaults, not the `v2` values `solve` applies (`budgetRounds` shown off, `lines` shown M0). The interface cannot express third-party consent or `--private` (`solve --ask-stdin` without `--lit` keeps the literature and remote `lean.search` silently off). The CLI prints nothing between setup and the end of a turn. Screens show claim ids instead of statements. The CLI help is one 200-line block for 40 commands. A first real run still costs about an hour and 15 GB.

## Changes

Ranked by impact over effort. Effort: XS under an hour, S under a day, M a few days, L a week or more. Kind as in earlier plan changes: MOD modifies a module, ADD adds within one, NEW is a new module.

## Order

UX1 and UX2 first (they mislead the user and are a day each), then UX4, UX5, UX7, UX12 and UX14 (one small pull request of visibility fixes), then UX3, UX6 and UX8, then UX9 to UX11, UX13 and UX15. UX16 is its own task after PR #4 merges, because it builds on `scripts/setup.sh` and `install.md`.

## What does not change

No trust rule moves: the interface still contains no research logic, cannot change a claim's status, and every new control maps to an existing flag or settings key. Consent (UX6) keeps the rule that no answer is no, and `--private` still wins over everything. Global Constraints 13 (no model id in the repository, so the `recommended` list lives in the host profile, not in code) and the shared-file rules of CLAUDE.md apply to `parameters.ts`, `cli.ts` and the host profiles.
